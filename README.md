# Nedaka.（寝高） — Frontend

睡眠記録を株価チャートに見立てて可視化するアプリ「Nedaka.」のフロントエンドです。
[バックエンドAPI](https://github.com/yukisatodev/nedaka-backend)から取得したデータを、ローソク足チャートとして描画します。

- デモ（ログイン不要）: https://gregarious-pony-811702.netlify.app/demo
- バックエンド: [nedaka-backend](https://github.com/yukisatodev/nedaka-backend)（ドメインロジック・API仕様はこちらに記載）

---

## 1. 背景

バックエンド側の詳しい制作背景は[nedaka-backendのREADME](https://github.com/yukisatodev/nedaka-backend)にまとめている。フロントエンドでは特に、**「ローソク足チャートを外部グラフライブラリに頼らず、SVGで自分で組み立てる」**ことにこだわった。ポートフォリオサイトのスキルレーダーチャートを座標計算から自作した経験を、別の形のデータ可視化に応用している。

## 2. 要件定義

### 2.1 想定ユーザー

バックエンドと同一。加えて「ログイン前に中身を試したい訪問者（採用担当・クライアント含む）」も一次的なユーザーとして想定している。

### 2.2 機能要件

| ID | 要件 | 対応状況 |
|---|---|---|
| F-1 | アカウント登録・ログインができる | ✅ |
| F-2 | 就寝/起床時刻と中途覚醒回数をフォームから記録できる | ✅ |
| F-3 | 記録をローソク足チャートとして表示する | ✅ |
| F-4 | 7日・30日移動平均線をチャートに重ねて表示する | ✅ |
| F-5 | 直近の値動き一覧（日付・スコア・コメント）を表示する | ✅ |
| F-6 | ログインなしでサンプルデータのデモ画面を閲覧できる | ✅ |
| F-7 | 決算レポート風PDFをダウンロードできる | ✅ |

### 2.3 非機能要件

- **初見での理解しやすさ**: 初めて訪れた人がまず迷わず内容を把握できるよう、トップをデモ画面（`/demo`）にし、ログイン不要でチャート・コメント・PDFまで即座に試せる導線にしている
- **一貫性**: ポートフォリオサイト・Site Checkと共通のデザイントークン（色・フォント）を使用

## 3. 画面構成

| ページ / コンポーネント | 役割 |
|---|---|
| `pages/Demo.jsx` | ログイン不要のデモ画面。サンプルデータでチャート・コメント・PDFを表示 |
| `pages/Login.jsx` / `pages/Register.jsx` | 認証画面 |
| `pages/Dashboard.jsx` | ログイン後のメイン画面。記録フォーム・チャート・直近の値動き一覧 |
| `components/CandlestickChart.jsx` | ローソク足チャート本体（SVG自作） |
| `components/EntryForm.jsx` | 睡眠記録の入力フォーム |
| `AuthContext.jsx` | ログイン状態をアプリ全体で共有するコンテキスト |
| `api.js` | バックエンドとの通信 |

ルーティングは`react-router-dom`で構成し、未ログイン時は`Dashboard`にアクセスすると`Login`にリダイレクトする。

## 4. 技術選定

| 技術 | 採用理由 |
|---|---|
| React + Vite | Site Checkと同じ構成で開発速度を確保 |
| React Router | デモ/ログイン/登録/ダッシュボードの複数画面を扱うため、Site Checkでは不要だったルーティングを初めて導入 |
| 自作SVGローソク足チャート | 外部グラフライブラリ不使用。始値・高値・安値・終値から矩形とヒゲの座標を自分で計算している |
| 素のCSS | ポートフォリオサイト・Site Checkと共通のデザイントークン |

## 5. セットアップ

```bash
npm install
npm run dev
```

`http://127.0.0.1:5173` が開く。バックエンドのURLを変更したい場合は`.env`に以下を設定する。

```
VITE_API_BASE_URL=http://127.0.0.1:8000
```

## 6. デプロイ

Netlifyで`npm run build`の`dist/`を公開。環境変数`VITE_API_BASE_URL`にビルド時の値が埋め込まれるため、本番バックエンドURL（Render）を変更した場合は再デプロイが必須。
